# asn1c-runtime

`asn1c-runtime` is the safe Rust runtime crate for Rust code generated by
asn1c. It provides primitive BOOLEAN, NULL, and bounded signed `i64` INTEGER
encoding and decoding for UPER, APER, and OER; CER encoding and strict CER
decoding; and BER decoding plus DER encoding. This is a bounded primitive
subset, not complete ASN.1 codec or type coverage.

The crate also has JER encode/decode functions for BOOLEAN, NULL, finite
bounded signed `i64` INTEGER, direct nonextensible ENUMERATED, and fixed-size
OCTET STRING and BIT STRING plus bounded-size OCTET and BIT STRING.
ENUMERATED root names encode as compact quoted JSON strings; OCTET STRING
values encode as quoted uppercase hexadecimal, and bounded BIT STRING values
include their exact logical length in the C-compatible object form. Their decoders
accept one complete token with JSON whitespace around it and reject unknown
names, escapes, malformed hex, incorrect fixed sizes, trailing values, and
out-of-range bounded sizes or exhausted input, output, or work limits. The
primitive decoders report
consumption of the entire supplied input.
`-0` decodes as zero; integer output uses minimal decimal notation. JER does
not yet provide streaming or constructed-value codecs. Consumers that
represent JSON numbers as floating point should verify that their chosen
parser preserves the full signed 64-bit range.

The crate uses Rust 2021 and only the standard library. It forbids unsafe Rust.
Input, output, and bit-work limits are caller-configurable through `Limits`;
the defaults are 1 MiB for input, 1 MiB for output, and 8 MiBits of work per
operation. CER and DER encoding use the output and work limits; input limits
apply to the entire supplied decode slice, including any unused suffix. BER
and strict CER decoding charge the TLV octets times eight against the work
limit. Prefix decoders report both meaningful bits and whole bytes consumed.

```rust
use asn1c_runtime::{decode_boolean, encode_boolean, encode_boolean_cer, Limits};

let limits = Limits::default();
let encoded = encode_boolean(true, &limits)?;
assert_eq!(encoded.bytes, [0x80]);
assert_eq!(encoded.bit_len, 1);

let decoded = decode_boolean(&encoded.bytes, &limits)?;
assert!(decoded.value);
assert_eq!(decoded.consumed_bits, 1);

let cer = encode_boolean_cer(true, &limits)?;
assert_eq!(cer.bytes, [0x01, 0x01, 0xff]);
assert_eq!(cer.bit_len, 24);
# Ok::<(), asn1c_runtime::Error>(())
```

For PER, `Encoded.bit_len` excludes final-byte padding. BOOLEAN decoding reads the most
significant bit and preserves the C decoder's permissive handling of the
remaining padding bits. A complete zero-width UPER value is represented by one
zero byte with `bit_len == 0`; decoding an empty slice requests more input, and
a nonzero zero-width byte is invalid. Constrained INTEGER decoding rejects
spare bit patterns outside the declared range. CER results contain complete
TLV bytes, so `bit_len` equals `bytes.len() * 8`. The runtime exposes
`encode_boolean_cer`, `encode_null_cer`, and `encode_integer_cer`, plus strict
`decode_boolean_cer`, `decode_null_cer`, and `decode_integer_cer`. The decoders
require the exact universal tag and a short-form definite length (long-form
and indefinite lengths are rejected), BOOLEAN content `00` or `FF`, empty NULL
content, and 1 to 8 minimal two's-complement INTEGER octets within the bounds;
invalid bounds are reported first. Trailing bytes are left unconsumed, and
`consumed_bytes`/`consumed_bits` describe the TLV. Generated Rust wrappers
expose `encode_cer` and `decode_cer` methods when CER is selected.

`encode_*_aper` and `decode_*_aper` provide aligned PER primitive prefixes.
Each call begins at an octet boundary; the APIs do not compose fields inside
constructed values. APER BOOLEAN uses one meaningful bit, NULL and singleton
INTEGER use one zero filler octet with zero meaningful bits. Bounded INTEGER
applies the aligned range thresholds and checks spare codes. `encode_*_oer`
and `decode_*_oer` provide
octet-aligned primitive prefixes. OER BOOLEAN emits `00`/`FF` and accepts any
nonzero truth octet on decode; NULL uses an empty prefix. OER INTEGER encodes
the value itself in the fixed signed or unsigned 1, 2, 4, or 8-octet width
selected by its finite bounds. These operations enforce the same configurable
input, output, and work limits as the existing primitive APIs. Generated
wrappers expose `encode_aper`/`decode_aper` and `encode_oer`/`decode_oer` when
the corresponding `-gen-*` option is selected.
The aligned integer thresholds follow [ITU-T X.691 (2021)](https://www.itu.int/rec/T-REC-X.691/en),
and the fixed OER integer widths follow [ITU-T X.696 (2021)](https://www.itu.int/rec/T-REC-X.696/en).

`UperWriter` and `UperReader` compose direct BOOLEAN, NULL, finite bounded
`i64` INTEGER, fixed OCTET STRING, and fixed BIT STRING fields into one
continuous UPER value. They enforce the input
size once for the complete supplied slice, check output growth against the
complete output limit, and charge `max_work_bits` cumulatively: each field
costs its meaningful wire bits plus eight work units. NULL and singleton
INTEGER fields therefore still consume budget despite using zero wire bits.
The cursors add or check the one-byte zero-width filler only when finishing
the complete value. A failed field operation leaves the logical cursor
position and work count unchanged. Generated Rust uses these cursors for
flat SEQUENCE types when UPER is the only selected codec.
The string cursor methods validate exact lengths, require zero unused low BIT
STRING bits on write, and preserve bit position across field boundaries.

`encode_boolean_der`, `encode_null_der`, and `encode_integer_der` emit canonical
primitive TLVs. Their bytes match CER for this subset. `decode_boolean_ber`,
`decode_null_ber`, and `decode_integer_ber` read one definite-length universal
primitive TLV and report prefix consumption. BER decoding accepts long-form
lengths, including redundant leading length octets, and any nonzero BOOLEAN
content octet as true. It requires a single BOOLEAN content octet and rejects
indefinite primitive lengths. INTEGER decoding accepts redundant leading sign
octets when the value still fits `i64`; that acceptance follows the C decoder
but extends the X.690 INTEGER wire rule. The generator exposes `encode_der` and
`decode_ber` only when `-gen-BER` is selected.

CBOR primitive APIs encode BOOLEAN, NULL, bounded signed INTEGER and opaque
ANY. They decode one definite prefix, accept leading semantic tags and
nonminimal definite heads, and reject INTEGER bignum tags and indefinite byte
strings. ANY is represented as a definite CBOR byte string and is limited to
`INT32_MAX` octets for compatibility with the C `ANY_t` size field.

`cbor::encode_map` and `cbor::decode_map` support generated flat SEQUENCE
values as definite text-key maps. The encoder preserves entry order and rejects
duplicate keys or non-complete CBOR values. The decoder accepts leading tags
and nonminimal definite heads, rejects duplicate keys, and returns borrowed
complete value spans. Unknown definite nested values can be skipped up to 64
levels; indefinite items and invalid UTF-8 text keys remain unsupported. The
generated decoder validates
each known value consumes its entire span and checks required members.

Direct fixed or bounded OCTET STRING values use definite CBOR byte strings.
BIT STRING values add one leading payload octet for the unused-bit count,
matching C; the decoder checks exact meaningful bit length and zero padding.
Both paths enforce the declared SIZE range and caller resource limits.

Generated CBOR CHOICE values use one-entry text-key maps. Top-level typed
CONTAINING wrappers place complete inner BOOLEAN or bounded INTEGER CBOR bytes
inside those BIT/OCTET string encodings; BIT contents must be octet aligned.
The narrow IOC-selected OPEN TYPE uses a two-field SEQUENCE map with the
selector and a direct selected CBOR value. Decoding accepts either field order,
skips unique unknown keys, rejects duplicates and missing fields, and checks
the selected value consumes its full encoded span.

The XER writer supports bounded basic XML output for generated flat SET and
SEQUENCE records. The generator currently accepts BOOLEAN, bounded INTEGER,
unconstrained IA5String fields, and REAL DEFAULT 0.5 with finite limited values only. XER decoding is not implemented.
IA5 C0 controls other than tab, line feed, and carriage return are rejected;
REAL values must survive a round trip through the emitted decimal text.
